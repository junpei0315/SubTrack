# 機能要件（Feature Requirements）

PRD で定義したプロダクト要件を、**実装単位（F-01〜F-14）**に分解した仕様。画面文言・バリデーション・ビジネスルールの参照元とする。

---

## 機能一覧（F-01〜F-14）

### 登録・管理

- **F-01**: サブスクリプション登録（プリセット選択）
- **F-02**: サブスクリプション新規追加（カスタム）
- **F-03**: サブスクリプション編集
- **F-04**: サブスクリプション削除

### ダッシュボード・可視化

- **F-05**: 月額・年額合計の表示
- **F-06**: ジャンル別支出の内訳表示
- **F-07**: 支出推移グラフ（月別）

### 使用頻度

- **F-08**: 使用チェック（今日使ったをワンタップ記録）
- **F-09**: 使用頻度・1回あたりコストの表示

### リマインド・通知

- **F-10**: 更新日リマインド通知
- **F-11**: 未使用サービスのアラート

### 設定

- **F-12**: 通知タイミング設定
- **F-13**: 通貨・表示形式の設定
- **F-14**: アカウント管理

## F-01: サブスクリプション登録（プリセット選択）

### 概要

プリセットされたサービス一覧からジャンルを絞り込み、契約中のサブスクを選択して登録できる。

### 前提条件

- ユーザーがアプリにログインしている

### 機能詳細

1. ジャンル（動画・音楽・交通・AI・仕事・学習・ゲーム・その他）でサービス一覧をフィルタリングできる
2. 一覧からサービスを選択（複数可）して一括登録できる
3. 選択時に金額・更新日などの詳細（クレジットカード）を入力または確認できる
4. 一覧にないサービスは「新規追加（F-02）」から登録できる

### 完了条件

- 選択したサービスが登録一覧・合計金額に即時反映される

### ビジネスルール

| 条件 | システム挙動 |
| --- | --- |
| 年額契約のサービス | 月額換算（÷12）して合計に含める |
| すでに登録済みのサービス | 一覧上でグレーアウト・選択不可にする |

### エラー・例外

| エラー条件 | システムの振る舞い |
| --- | --- |
| 金額・更新日が未入力のまま登録しようとした | 該当項目をハイライトしエラー表示、登録不可 |
| 通信エラーで保存失敗 | 失敗トーストを表示し再試行を促す |

---

## F-02: サブスクリプション新規追加（カスタム）

### 概要

プリセットにないサービスを、ユーザーが入力して登録する。

### 前提条件

- ユーザーがアプリにログインしている

### 機能詳細

1. サービス名、金額、支払サイクル（月額/年額）、ジャンルを任意に入力可能
2. 登録時に金額・更新日などの詳細を入力または確認できる
3. 任意のアイコンの設定（拡張要素）

### 完了条件

- 入力内容が保存され、登録一覧・合計金額に即時反映される

### ビジネスルール

| 条件 | システム挙動 |
| --- | --- |
| 年額契約のサービス | 月額換算（÷12）して合計に含める |

### エラー・例外

| エラー条件 | システムの振る舞い |
| --- | --- |
| 必須項目が未入力 | 該当項目を赤字でハイライトし、登録ボタンを非活性にする |
| 入力された金額が不正（マイナス値など） | 「0以上の数値を入力してください」とエラー文言を表示 |
| サービスの重複 | 登録済みとアラート |

---

## F-03: サブスクリプション編集

### 概要

登録済みのサブスクリプションのプラン、更新日などの情報を変更する。

### 前提条件

- ユーザーがアプリにログインしており、1つ以上のサービスを登録している

### 機能詳細

1. 登録済みサブスクリプションの詳細画面から「編集」モードへ遷移できる
2. 一時的な利用停止状態に切り替えるトグルを設定できる

### 完了条件

- 変更内容が保存され、一覧画面やダッシュボードの計算に即時反映される

### ビジネスルール

| 条件 | システム挙動 |
| --- | --- |
| 金額・周期が変更された場合 | 変更保存後のダッシュボード合計金額を即座に再計算する |
| 一時停止（ポーズ）に設定された場合 | 一覧上でグレーアウト表示とし、毎月の合計金額の計算から除外する |

### エラー・例外

| エラー条件 | システムの振る舞い |
| --- | --- |
| 通信エラーによる保存失敗 | 失敗トーストを表示し再試行を促す |

---

## F-04: サブスクリプション削除

### 概要

解約した、または管理不要になったサブスクリプションをアプリ内から削除する。

### 前提条件

- 対象のサブスクリプションが登録されている

### 機能詳細

1. 詳細・編集画面の「削除」ボタンから実行できる
2. 誤操作防止のため、削除実行前に確認ダイアログを表示する

### 完了条件

- 対象のデータがリストから消去され、ダッシュボードの合計金額から除外される

### ビジネスルール

| 条件 | システム挙動 |
| --- | --- |
| 削除の実行 | 過去の支払い履歴データごと削除する（※または「解約済」としてアーカイブに残す仕様にするか要件定義次第） |

### エラー・例外

| エラー条件 | システムの振る舞い |
| --- | --- |
| 削除処理中のネットワーク切断 | 削除処理をロールバックし、一覧に表示したままエラーメッセージを出す |

---

## F-05: 月額・年額合計の表示

### 概要

ダッシュボード上で、現在契約しているサブスクリプションの総合計金額を可視化する。

### 前提条件

- 登録済みのサブスクリプションが存在する

### 機能詳細

1. タブまたはトグルスイッチで「月額合計」と「年額合計」の表示を即座に切り替えられる
2. 次回支払い予定の合計額を大きく表示する

### 完了条件

- 登録データに基づいた正確な計算結果が画面に表示される

### ビジネスルール

| 条件 | システム挙動 |
| --- | --- |
| 月額表示時の計算式 | （月額サービス合計）＋（年額サービス÷12）＋（週額サービス×4.3） |
| 年額表示時の計算式 | （年額サービス合計）＋（月額サービス×12）＋（週額サービス×52） |

### エラー・例外

| エラー条件 | システムの振る舞い |
| --- | --- |
| 登録データが0件 | 「＋ボタンからサブスクを登録しましょう」という空状態を表示 |

## F-06: ジャンル別支出の内訳表示

### 概要

動画、音楽、学習などのジャンルごとに、どれだけコストをかけているかをグラフで可視化する。

### 前提条件

- 登録済みのサブスクリプションが存在し、それぞれにジャンルが割り当てられている

### 機能詳細

1. ダッシュボード上にドーナツチャート（または円グラフ）でジャンル別の比率を表示する
2. グラフの各セグメント（ジャンル）をタップすると、そのジャンルに含まれる具体的なサービス一覧がポップアップ表示される

### 完了条件

- 支出比率に応じた正確なグラフが描画される

### ビジネスルール

| 条件 | システム挙動 |
| --- | --- |
| 割合が非常に小さいジャンル | 視認性確保のため、グラフ上では「その他」として自動的にまとめる |
| すべて同じ金額・ジャンルの場合 | 100%単色のグラフとして正常に描画する |

### エラー・例外

| エラー条件 | システムの振る舞い |
| --- | --- |
| （未定） | （未定） |

## F-07: 支出推移グラフ（月別）

### 概要

過去数ヶ月の支出履歴と、今後の支払い予定（推移）を棒グラフ等で表示する。

### 前提条件

- ユーザーがアプリを利用開始してからデータが蓄積されている、または更新日が設定されている

### 機能詳細

1. 横軸を月、縦軸を金額としたグラフを表示する
2. 新規追加や解約予定を反映し、「来月の想定支出」を予測表示する（拡張機能）

### 完了条件

- 期間を切り替えても（過去6ヶ月、1年など）正しくデータが描画される

### ビジネスルール

| 条件 | システム挙動 |
| --- | --- |
| 未来の月の予測計算 | 現在アクティブなサブスクがそのまま継続される前提で計算する（解約予定日が設定されているものは除く） |

### エラー・例外

| エラー条件 | システムの振る舞い |
| --- | --- |
| 描画ライブラリの読み込み失敗 | グラフ領域に「データを読み込めませんでした」とテキスト表示 |

---

## F-08: 使用チェック（今日使ったをワンタップ記録）

### 概要

ユーザーがその日に対象のサブスクサービスを利用したかをワンタップで簡単に記録する。

### 前提条件

- 対象のサブスクリプションが登録されている

### 機能詳細

1. ホーム画面のサービスリストの横に「使った！」ボタン（チェックボックスなど）を配置する
2. ボタンをタップするとアニメーションが入り、本日の利用実績として記録される

### 完了条件

- タップ後、データベースに本日の利用ログ（タイムスタンプ）が保存される

### ビジネスルール

| 条件 | システム挙動 |
| --- | --- |
| 1日に複数回タップされた場合 | 「利用した日」としての記録であるため、同日中の重複タップは無視（状態を維持）するか、トグルでチェック解除とする |
| 日付の更新 | 深夜0時（端末のローカルタイム）を基準にチェック状態をリセットする |

### エラー・例外

| エラー条件 | システムの振る舞い |
| --- | --- |
| オフライン時のタップ | ローカルに一時保存し、オンライン復帰時にバックグラウンドで同期する |

---

## F-09: 使用頻度・1回あたりコストの表示

### 概要

F-08 のデータをもとに、サブスクの「元が取れているか（コストパフォーマンス）」を可視化する。

### 前提条件

- 対象サブスクの金額が設定されており、利用記録データが存在する

### 機能詳細

1. 各サービスの詳細画面にて、「今月の利用回数」と「1回利用あたりのコスト（月額÷利用回数）」を表示する
2. 過去の平均利用頻度を表示する

### 完了条件

- 最新の利用チェック情報に基づいて、即座に1回あたりのコストが再計算・表示される

### ビジネスルール

| 条件 | システム挙動 |
| --- | --- |
| 今月の利用回数が0回の場合 | 計算エラー（ゼロ除算）を防ぐため、「1回あたりのコスト」は「未利用」または月額費用をそのまま赤字で表示する |

### エラー・例外

| エラー条件 | システムの振る舞い |
| --- | --- |
| 登録初日でデータ不足 | 「データ蓄積中」として計算結果をプレースホルダー（- 円）にする |

## F-10: 更新日リマインド通知

### 概要

サブスクリプションの課金更新日が近づいた際に、Push 通知でユーザーに知らせる。

### 前提条件

- OS 側およびアプリ内で通知設定がオンになっている。各サービスに更新日が設定されている

### 機能詳細

1. アプリを起動していなくても、指定されたタイミングでスマートフォンの Push 通知が届く
2. 通知をタップすると、対象サービスの「詳細画面」へ直接遷移する

### 完了条件

- 設定された期日・時間に指定のメッセージ（例：「明日、Netflixの更新日です」）が配信される

### ビジネスルール

| 条件 | システム挙動 |
| --- | --- |
| アプリを長期間起動していない | ローカル通知機能（OS のスケジュール機能）を利用し、オフラインでも通知を発火させる |

### エラー・例外

| エラー条件 | システムの振る舞い |
| --- | --- |
| OS の通知権限がオフ | アプリ内ホーム画面の上部に「更新日をお知らせするため、通知をオンにしてください」とバナーを表示する |

## F-11: 未使用サービスのアラート

### 概要

長期間利用されていない（使用チェックがない）サブスクリプションを検知し、見直しを促す。

### 前提条件

- F-08 の使用チェック機能を利用している

### 機能詳細

1. 一定期間（例：30日間）利用ログがないサービスに対して、ダッシュボード上に「見直し推奨アラート」を表示する
2. アラートから直接解約手続きのメモを見たり、アプリ上の削除（解約済）操作ができる

### 完了条件

- 条件を満たしたサービスがアラート一覧に正しくリストアップされる

### ビジネスルール

| 条件 | システム挙動 |
| --- | --- |
| 年額契約のサービス | 月額サービスよりも長期的な利用を想定するため、アラート基準を「90日未利用」などに自動で変更する |

### エラー・例外

| エラー条件 | システムの振る舞い |
| --- | --- |
| まったく使用チェック機能を使っていないユーザー | すべてのサービスが未利用判定になるのを防ぐため、アラート機能自体を非アクティブ（無効）にする |

---

## F-12: 通知タイミング設定

### 概要

F-10 の更新日リマインド通知を受け取るタイミングを、ユーザーの好みに合わせて変更する。

### 前提条件

- アプリの通知設定が有効である

### 機能詳細

1. 設定画面から、デフォルトの通知タイミング（当日、1日前、3日前、1週間前）を選択できる
2. サービスごとに個別の通知タイミングをオーバーライド（個別設定）できる

### 完了条件

- 設定内容がデータベースに保存され、次回のスケジュール通知から適用される

### ビジネスルール

| 条件 | システム挙動 |
| --- | --- |
| 複数サービスの更新日が同日の場合 | 通知が連続して鳴らないよう、1つの Push 通知にまとめて（例：「他2件の更新があります」）配信する |

### エラー・例外

| エラー条件 | システムの振る舞い |
| --- | --- |
| 設定保存時のエラー | 変更前の設定に戻し、「設定を保存できませんでした」と表示する |

---

## F-13: 通貨・表示形式の設定

### 概要

海外のサブスクサービス利用時などに対応するため、通貨の切り替えや日付の表示形式を変更できる。

### 前提条件

- 特になし（ログイン直後から利用可能）

### 機能詳細

1. ベース通貨の設定（JPY / USD / EUR など）を変更できる
2. サブスク登録時にサービス単体での通貨も設定可能にし、ベース通貨に合わせて為替換算して表示する

### 完了条件

- 設定変更後、ダッシュボードを含むすべての金額表記が即座に切り替わる

### ビジネスルール

| 条件 | システム挙動 |
| --- | --- |
| 異なる通貨での合計計算 | 一定の固定レート（または1日1回更新の API レート）を用いてベース通貨に換算し、合計金額を算出する |

### エラー・例外

| エラー条件 | システムの振る舞い |
| --- | --- |
| 為替 API の取得失敗 | 最後に取得成功したキャッシュのレートを使用して計算し、「一部最新の為替レートが反映されていません」と注記を出す |

## F-14: アカウント管理

### 概要

ユーザーの基本情報の変更、データのバックアップ、ログアウト・退会処理を行う。

### 前提条件

- ユーザーがログインしている

### 機能詳細

1. メールアドレス、パスワードの変更ができる
2. 機種変更時のためのクラウドバックアップ（エクスポート）ができる
3. アカウント削除（退会）処理を実行できる

### 完了条件

- 各アクションが正常に処理され、退会の場合は関連するすべてのユーザーデータが破棄される

### ビジネスルール

| 条件 | システム挙動 |
| --- | --- |
| アカウント削除実行時 | 「元に戻すことはできません」という最終確認を表示し、同意を示すテキスト入力（例: `DELETE` と入力）を必須とする |

### エラー・例外

| エラー条件 | システムの振る舞い |
| --- | --- |
| パスワード変更時のバリデーションエラー | 「8文字以上の英数字を入力してください」等、条件を満たしていない箇所をリアルタイムで指摘する |
